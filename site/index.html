Mock any API response, right in Chrome.

Mockingmoo is a Chrome extension for API mocking. It intercepts fetch and XMLHttpRequest calls by URL and lets you mock, stub or rewrite the response in the browser, with no proxy and no change to your app's API URL.

See it in action

Install

  1. Download the zip from the latest release and unzip it, or clone the repository.
  2. Open chrome://extensions and turn on Developer mode.
  3. Click Load unpacked and select the folder.
  4. Pin the extension so the cow is one click away.

Your first mock

  1. Open the rules page and Import examples/sample-rules.json.
  2. Switch on Static: users list. Imported rules start paused.
  3. Run this in DevTools on any page:
const response = await fetch("/api/users");
const users = await response.json();
console.table(users.users);

You get Ada Lovelace and Grace Hopper instead of the real server's answer.

Rewrite a real response with a few lines of JS

The function receives the request and the real response, and returns the new body. Return undefined to leave it alone.

function modifyResponse({ requestData, responseJSON }) {
  // Only touch the GraphQL operation we care about.
  if (requestData?.operationName !== "GetCart") return undefined;

  return { ...responseJSON, data: { cart: { items: [] } } };
}

Questions

Is Mockingmoo free?

Yes. It's open source under the MIT license, with no account, paid tier or telemetry.

Does it work with GraphQL?

Yes. JS rules receive the parsed request body, so you can match on operationName and mock one operation while the rest pass through.

Why don't my JS rules run on some sites?

JS rules use new Function, which pages with a strict Content Security Policy block. Static rules still work there.

Does it mock XHR as well as fetch?

Yes. For XHR the real request is still sent and only the response is swapped. "Skip the network" applies to fetch only.

The full guide, including limitations and the security notes, is in the README on GitHub.
